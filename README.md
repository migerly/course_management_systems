# Course Management System

**Лабораторна робота з дисципліни «Сучасні технології баз даних»**

## Опис проєкту

**Course Management System** — навчальна інформаційна система для управління онлайн-курсами, студентами, викладачами та навчальним процесом.

Проєкт демонструє проєктування реляційної бази даних PostgreSQL, використання механізмів забезпечення цілісності даних, збережених процедур, функцій, тригерів, представлень (VIEW) та індексів.

Окрему увагу приділено взаємодії Java-застосунку з базою даних за допомогою JDBC та реалізації патернів **Repository і Unit of Work**.

## Використані технології

- **Java** — реалізація програмної логіки.
- **PostgreSQL** — реляційна система керування базами даних.
- **JDBC** — взаємодія Java із PostgreSQL.
- **Maven** — керування залежностями та збирання проєкту.
- **PostgreSQL** — реалізація процедур, функцій і тригерів.
- **IntelliJ IDEA** — середовище розробки.
- **dbdiagram.io** — побудова ER-діаграми.

## 1. Проєктування бази даних

Розроблено реляційну модель, що складається з **18 взаємопов'язаних таблиць**.

### Основні сутності

| Таблиця | Призначення |
|---|---|
| `users` | Користувачі системи |
| `roles` | Ролі користувачів |
| `user_roles` | Призначення ролей |
| `categories` | Категорії курсів |
| `courses` | Навчальні курси |
| `course_offerings` | Окремі потоки проведення курсів |
| `offering_instructors` | Викладачі навчальних потоків |
| `enrollments` | Реєстрація студентів |
| `modules` | Модулі курсів |
| `lessons` | Навчальні уроки |
| `lesson_materials` | Матеріали уроків |
| `assignments` | Навчальні завдання |
| `submissions` | Відповіді студентів |
| `grades` | Оцінки за виконані завдання |
| `lesson_progress` | Прогрес проходження уроків |
| `announcements` | Оголошення |
| `discussions` | Обговорення |
| `discussion_messages` | Повідомлення в обговореннях |

Зв'язки між сутностями реалізовано за допомогою первинних (PRIMARY KEY) і зовнішніх ключів (FOREIGN KEY).

Для забезпечення цілісності даних використовуються обмеження `NOT NULL`, `UNIQUE`, `CHECK` та `REFERENCES`.

## 2. Soft Delete та аудит змін

У низці таблиць реалізовано механізм **Soft Delete** — логічне видалення без фізичного вилучення запису з бази даних.

Для цього використовуються поля:

- `deleted_at` — дата й час видалення;
- `deleted_by` — користувач, який виконав видалення.

Для відстеження змін використовуються:

- `created_at` — дата створення запису;
- `updated_at` — дата останнього оновлення;
- `updated_by` — користувач, який виконав останню зміну.

Автоматичне оновлення `updated_at` забезпечується тригерами.

## 3. Збережені процедури, функції, тригери та VIEW

У PostgreSQL реалізовано серверну логіку для роботи з навчальними даними.

**Збережені процедури** використовуються для створення та зміни записів, зокрема для створення курсу, логічного видалення і відновлення курсу, здавання завдань та завершення уроків.

**Користувацькі функції** використовуються для перевірки прав доступу та реалізації допоміжної логіки.

**Тригери** забезпечують автоматичне оновлення службових полів.

**Представлення (VIEW)** надають доступ до підготовлених наборів даних, зокрема:

- `v_active_courses` — активні курси;
- `v_active_modules` — активні модулі;
- `v_active_lessons` — активні уроки;
- `v_active_lesson_materials` — доступні навчальні матеріали;
- `v_student_results` — результати навчання студентів.

Представлення дозволяють централізувати SQL-запити та приховувати логічно видалені записи.

## 4. Індексація

Для оптимізації виконання запитів використовуються два типи індексів PostgreSQL:

**B-tree** — для пошуку, фільтрації та з'єднання записів за ключовими полями.

**GIN** — для повнотекстового пошуку курсів за назвою та описом.

Також реалізовано часткові індекси, що враховують лише записи, які не були логічно видалені.

## 5. Архітектура Java-застосунку

Для організації доступу до бази даних використовується комбінація патернів **Repository + Unit of Work**.

### Repository Pattern

Кожен репозиторій відповідає за роботу з певною групою даних.

У проєкті реалізовано:

- `SubmissionRepository` — здавання студентських робіт;
- `ProgressRepository` — оновлення прогресу навчання;
- `StudentResultRepository` — отримання результатів студентів.

Усі SQL-запити репозиторіїв виконують через збережені процедури або представлення бази даних.

### Unit of Work Pattern

Клас `UnitOfWork` керує спільним JDBC-з'єднанням і транзакцією для кількох репозиторіїв.

Основні можливості:

- відкриття з'єднання з PostgreSQL;
- вимкнення автоматичного підтвердження транзакцій;
- виконання кількох операцій у межах однієї транзакції;
- підтвердження змін через `commit()`;
- скасування незавершених змін через `rollback()`;
- закриття з'єднання після завершення роботи.

### Приклад роботи

Метод `LearningService.submitAndComplete()` виконує дві пов'язані операції:

1. Збереження відповіді студента на завдання.
2. Позначення уроку як завершеного.

Обидві операції виконуються в межах одного Unit of Work.

Якщо всі операції успішні, транзакція підтверджується. У випадку помилки незавершена транзакція відкочується.

Цей підхід забезпечує атомарність виконання пов'язаних операцій.

## 6. Налаштування та запуск

Для запуску необхідні:

- JDK відповідної версії;
- PostgreSQL;
- Maven;
- створена база даних із виконаним SQL-скриптом.

Параметри з'єднання передаються через змінні середовища:

```text
DB_URL=jdbc:postgresql://localhost:5432/course_management
DB_USER=postgres
DB_PASSWORD=<your_password>
```

Паролі не повинні зберігатися у відкритому репозиторії.

Для компіляції Maven-проєкту:

```bash
mvn clean compile
```

Для запуску Java-програми використовується клас `org.example.Main`.

Програма підтримує перегляд результатів студентів та виконання операції здавання завдання із завершенням уроку.

3. Передбачено механізми Soft Delete та аудиту змін.
4. Реалізовано серверну логіку PostgreSQL із використанням процедур, функцій, тригерів та VIEW.

6. Розроблено Java-класи для роботи з пов'язаними сутностями бази даних.

8. Передбачено транзакційну обробку пов'язаних операцій.

## Висновок

Розроблений проєкт демонструє комплексний підхід до організації реляційної бази даних і взаємодії з нею на рівні Java-застосунку.

Використання обмежень цілісності, тригерів, процедур та транзакцій дозволяє підвищити надійність операцій із даними.

Патерни Repository та Unit of Work допомагають розділити логіку доступу до даних і бізнес-операції, забезпечуючи зрозумілу та розширювану архітектуру застосунку.
